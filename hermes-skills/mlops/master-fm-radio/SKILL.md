# Master-FM: AI-radio automation

Full pipeline for Master-FM radio station on Beelink SER9 (Ryzen 7 255, Radeon 780M, 24 GB RAM).
Uses Qwen3-TTS 1.7B-Base on GPU via torch-directml (skill `qwen3-tts-directml`) for voice generation.

## Architecture

```
ai-radio/
├── config.yaml              # Radio config (schedule, styles, paths, presets)
├── scripts/
│   ├── dj.py                # DJ: playlist building, ffmpeg stream :8090/radio
│   ├── night_batch.py       # Night batch (20:00-07:00): full content generation
│   ├── day_breaking_news.py # Day mode (07:00-20:00): breaking news only
│   ├── gen_music.py         # Music generation via ACE-Step (CPU) — preset-driven
│   ├── gen_voice_content.py # Voice content generation (news, ads, jingles) — emotional styles
│   ├── gpu_tts_test.py      # Low-level Qwen3-TTS 1.7B test on DML (BROKEN)
│   ├── gpu_tts_test_cpu.py  # Low-level Qwen3-TTS 0.6B test on CPU (WORKING)
│   └── gpu_tts_cli.py       # CLI wrapper for GPU/CPU-TTS (Voicebox-compatible)
├── cache/                   # Content cache (music, news, ads, jingles, audiobooks)
└── logs/
```

## Preset System (gen_music.py)

```bash
# 6 presets with tier-aware defaults
python gen_music.py --preset music_block   # 180s, 2 tracks, bpm=130
python gen_music.py --preset jingle        # 10s, 4 tracks, bpm=140, temp=0.7
python gen_music.py --preset bed           # 45s, 3 tracks, bpm=100, temp=0.9
python gen_music.py --preset news_bed      # 30s, 2 tracks, bpm=90, C Major
python gen_music.py --preset ad_bed        # 20s, 3 tracks, bpm=120
python gen_music.py --preset night_long    # 300s, 1 track, bpm=70

# Override any preset parameter
python gen_music.py --style rock --duration 240 --count 4 --preset music_block
```

**Key ACE-Step parameters baked into presets:**
- `shift=3.0` (critical for turbo model structure)
- `thinking=true` (LM metadata + codes)
- `inference_steps=8` (turbo fixed)
- `infer_method=ode` (deterministic)
- `offload_to_cpu=true`, `offload_dit_to_cpu=true`

## Operation Modes

### Night Batch (20:00-07:00)
**Cron:** `0 20 * * *` -> `scripts/night_batch.py`
- Full content generation for the day
- Music (all styles, 10 tracks/style, 3 min)
- News (all categories)
- Ads, jingles, audiobooks
- Runs as Hermes cron job with skill `qwen3-tts-directml`

### Day Mode (07:00-20:00)
**Cron:** `*/15 7-19 * * *` -> `scripts/day_breaking_news.py`
- Only breaking news via **CPU-TTS (Qwen3-TTS 0.6B Base)** — GPU 1.7B broken
- Everything else (music, ads, jingles) from cache
- Generates 1-2 breaking news per run in random categories
- Skips category if cache has >=5 files

## DJ Streaming
`scripts/dj.py` - continuous MP3 stream at `http://localhost:8090/radio`
- 5-second ring buffer for late joiners
- Professional ffmpeg mastering chain (highpass, gate, EQ, loudnorm, compand, limiter)
- Builds playlist per schedule from `config.yaml`
- Daytime picks 2 random news from cache (breaking + regular mixed)

## Текущий статус GPU-TTS / CPU-TTS (2026-08-05) — GPU BROKEN, CPU-TTS 0.6B WORKS

### GPU-TTS (DirectML на Radeon 780M) — BROKEN для 1.7B модели

**GPU-TTS на Radeon 780M через DirectML сейчас НЕ РАБОТАЕТ** (segfault при любом inference):

| Этап | Результат |
|---|---|
| Загрузка на CPU (`from_pretrained`) | Работает (~20с, 480 тензоров из safetensors) |
| `.to(dml)` перенос модели | Segfault (exit 139) |
| CPU inference (без .to(dml)) | Segfault в `create_voice_clone_prompt` / `generate_voice_clone` |
| Пустой forward на CPU | AttributeError (неполная конфигурация модели) |
| torch-directml базовые операции | Работают (tensor.to(dml), matmul) |

**Конфигурация модели 1.7B:**
- Тип: Base (`tts_model_type: base`), 1.93B параметров
- Safetensors: 3.8 GB, 480 тензоров
- RAM требование: ~7.6 GB fp32 (не входит в доступную память ~1-2 GB)

**Диагностика:**
- `safetensors` читается успешно
- Пустая модель создаётся без ошибок
- `load_state_dict` падает с `OSError: Файл подкачки слишком мал` (даже при 32GB) или segfault
- Базовые DML операции работают — проблема в несовместимости Qwen3-TTS 1.7B с torch-directml 0.2.5 + transformers 4.57.3 + нехватка RAM

### CPU-TTS (0.6B Base model) — РАБОТАЕТ ✓

**Скрипт `day_breaking_news.py` использует 0.6B модель на CPU (fp32) и работает стабильно:**

| Этап | Результат |
|---|---|
| Загрузка модели 0.6B на CPU | Работает (~5-6с, ~3 GB fp32 RAM) |
| `create_voice_clone_prompt` | Работает |
| `generate_voice_clone` | Работает (~15-85с за фразу) |
| Память после завершения | Полностью освобождается |

**Модель:** `Qwen3-TTS-12Hz-0.6B-Base` (~1.5 GB fp16, ~3 GB fp32) — входит в доступную RAM.

**Влияние на Master-FM (актуальное):**

- ⚠️ Ночной батч (night_batch.py) — голосовые части могут использовать GPU-TTS, нужна проверка/миграция на CPU-TTS 0.6B

## ACE-Step Integration for Music Generation (2026-08-05)

### ACE-Step Working Path for Music
- **Gradio UI (http://127.0.0.1:7860) is the ONLY working generation path** for ACE-Step on Windows ROCm 7.2
- CLI generation (`python cli.py -c config.toml`) fails due to **transformers version conflict**:
  - `transformers 4.48.3`: Works for Gradio UI but **lacks `layer_type_validation`** needed for model config loading
  - `transformers 4.50+`: Has `layer_type_validation` but **imports FSDP** (`torch.distributed.tensor`) which is **missing in ROCm Windows build** → `ModuleNotFoundError: torch._C._distributed_c10d`
- **Solution**: Use Gradio Web UI for all ACE-Step music generation tasks

### Environment Isolation for ACE-Step
- **Hermes venv (Python 3.11) site-packages MUST be cleaned** to avoid conflicts with ACE-Step `venv_rocm` (Python 3.12)
- Key packages to remove from Hermes venv: `numpy`, `torch*`, `transformers*`, `tokenizers*`, `diffusers*`, `huggingface*`, `gradio*`, `fastapi*`, `pydantic*`, `scipy*`, `PIL*`, `bitsandbytes*`, `lycoris_lora*`
- Use `acectl free-gpu` to force GPU memory cleanup (calls `EmptyWorkingSet` on Windows)

### Transformers Version Deadlock for ACE-Step
- **No single transformers version works for both Gradio and CLI** on ROCm Windows:
  - `4.48.3`: Works for Gradio UI (no FSDP import), but ACE-Step model config requires `layer_type_validation` (added in 4.50+)
  - `4.50+`: Has `layer_type_validation`, but imports FSDP → fails on ROCm Windows (no `torch._C._distributed_c10d`)
- **Current workaround**: Use Gradio UI with transformers 4.48.3; CLI generation not available

## Breaking News Templates (in `scripts/day_breaking_news.py`)

4 categories x 4 events x 2 templates = 32 phrase variants.
Examples:
- world: "plane crash in Europe, casualties reported"
- tech: "largest data breach in history"
- sport: "doping scandal at Olympics"
- local: "chemical warehouse fire: smoke visible across city"

## Pitfalls

1. **DJ doesn't see breaking news** - verify `day_breaking_news.py` runs via cron and files appear in `cache/news/<cat>/breaking_*.wav`
2. **GPU-TTS OOM** - run only one synthesis process at a time; don't keep model in memory
3. **Two voicebox-server.exe** - port :8000 conflict; stop Voicebox when using GPU-TTS
4. **fp16 broken** - fp32 only; Mimi codec doesn't support Half on DML
5. **device_map breaks loading** - load on CPU -> `.to(dml)` + `tts.device = dml`
6. **Paging file too small for sequential CPU-TTS loads** - Windows paging file on Beelink SER9 insufficient for 2nd model load (~3 GB fp32); `day_breaking_news.py` keeps model in global memory causing `OSError: Файл подкачки слишком мал` on 2nd run. Fix: use separate subprocess per generation (like `gpu_tts_cli.py`) or increase Windows paging file.
